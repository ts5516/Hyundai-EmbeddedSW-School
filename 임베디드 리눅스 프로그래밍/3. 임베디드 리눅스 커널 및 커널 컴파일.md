# 임베디드 리눅스 커널 및 커널 컴파일

## 1. 임베디드 리눅스 커널 핵심

### 1.1. 메모리 관리

#### 메모리 계층 구조
- **개념**: CPU와 저장장치 간 속도 차이를 완화하기 위한 다계층 메모리 구조.
- **구성 (라즈베리 파이 4 기준)**
  - **레지스터**: 최고 속도, 최소 용량
  - **L1/L2 캐시**: 코어 내부/근접에 위치한 고속 캐시 메모리
  - **DRAM (메인 메모리)**: 실행 중인 프로그램과 데이터를 적재
  - **SD Card (보조 기억 장치)**: 영구 데이터 저장, 가장 느림

#### 가상 메모리
- **논리 주소**: 프로세스가 사용하는 독립적인 주소 공간.
- **물리 주소**: 실제 RAM 하드웨어의 주소.
- **MMU (Memory Management Unit)**: 논리 주소를 물리 주소로 변환하는 하드웨어.
- **ASLR (`randomize_va_space`)**: 보안 강화를 위해 프로세스 시작 주소를 무작위로 변경.

#### 페이징
- **개념**: 프로세스 메모리를 **페이지(Page)**, 물리 메모리를 **프레임(Frame)** 단위로 분할하여 매핑.
- **페이지 테이블**: 각 프로세스별로 페이지-프레임 매핑 정보를 저장.
- **TLB (Translation Look-aside Buffer)**: 페이지 테이블의 일부를 캐싱하는 고속 메모리로, 주소 변환 속도를 향상.
- **다중 레벨 페이지 테이블**: 페이지 테이블의 메모리 사용량을 줄이기 위한 계층적 구조.

#### 고급 메모리 관리 기법
- **요구 페이징**: 페이지가 실제 필요할 때만 메모리에 로드. 접근하려는 페이지가 없으면 **페이지 폴트(Page Fault)** 발생.
- **스와핑**: RAM 부족 시, 사용 빈도가 낮은 페이지를 디스크의 **스왑 영역**으로 이동.
- **쓰기 시 복사 (COW)**: `fork()` 시 메모리를 공유하고, 쓰기 작업이 발생하면 해당 페이지만 복사하여 효율 증대.

---

### 1.2. 예외 처리와 인터럽트

- **인터럽트**: **하드웨어**에 의해 발생하는 **비동기** 이벤트 (e.g., I/O 완료).
- **예외**: **소프트웨어**(명령어 실행) 중 발생하는 **동기** 이벤트 (e.g., 0으로 나누기).
- **트랩**: `System Call`처럼 의도적으로 발생시키는 예외.

- **리눅스 인터럽트 처리**:
  - **Top Half (상반부)**: 인터럽트 발생 즉시 실행. 최소한의 작업만 빠르게 처리.
  - **Bottom Half (하반부)**: 시간이 오래 걸리는 작업을 나중에 처리. (SoftIRQ, Tasklet, Workqueue)

---

### 1.3. 시스템 콜 인터페이스

- **역할**: 사용자 공간 앱이 커널의 기능을 안전하게 사용하도록 제공하는 통로.
- **동작 흐름**: 사용자 앱 → 라이브러리 함수 → `svc` (트랩) → 커널 모드 전환 → 커널 함수 실행 → 사용자 모드로 복귀.
- **주요 시스템 콜**:
  - **파일**: `open`, `read`, `write`, `close`
  - **프로세스**: `fork`, `execve`, `waitpid`
  - **메모리**: `mmap`, `brk`

---

### 1.4. 가상 파일 시스템 (VFS)

- **역할**: 다양한 파일 시스템(ext4, FAT32 등)에 일관된 API를 제공하는 커널의 추상화 계층.
- **장점**: `open`, `read` 등 표준 시스템 콜로 모든 종류의 파일 시스템에 동일하게 접근 가능.
- **리눅스 폴더 구조**:
  | 디렉토리      | 설명                                     |
  | ------------- | ---------------------------------------- |
  | `/`           | 루트 디렉토리                            |
  | `/bin`, `/sbin` | 필수 명령어                              |
  | `/etc`        | 시스템 설정 파일                         |
  | `/dev`        | 장치 파일                                |
  | `/proc`, `/sys` | 커널 및 시스템 정보 가상 파일 시스템     |
  | `/lib`        | 공유 라이브러리 및 커널 모듈             |
  | `/home`       | 사용자 홈 디렉토리                       |
  | `/boot`       | 부트로더 및 커널 이미지                  |

## 2. 임베디드 리눅스 커널 컴파일 (실습: 라즈베리 파이 4)

### 2.1. 개발 환경 구축 (WSL2)

1.  **WSL2 설치**:
    ```bash
    wsl --install
    ```
2.  **빌드 도구 및 의존성 설치**:
    ```bash
    sudo apt update && sudo apt upgrade -y
    sudo apt install git bc bison flex libssl-dev make libc6-dev libncurses5-dev -y
    sudo apt install crossbuild-essential-arm64 -y
    ```

### 2.2. 표준 커널 컴파일 및 설치

1.  **소스 코드 다운로드**:
    ```bash
    git clone --depth=1 --branch rpi-6.6.y https://github.com/raspberrypi/linux
    cd linux
    ```
2.  **기본 설정 적용**:
    ```bash
    KERNEL=kernel8
    make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- bcm2711_defconfig
    ```
3.  **커널 컴파일**:
    ```bash
    make -j$(nproc) ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- Image modules dtbs
    ```
4.  **SD 카드에 설치**:
    - `usbipd`로 SD 카드 연결 후, `boot`/`root` 파티션 마운트.
    - 컴파일된 파일들을 SD 카드에 복사.
      ```bash
      # 모듈 설치
      sudo make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- INSTALL_MOD_PATH=/mnt/root modules_install
      # 커널 이미지 및 DTB 복사
      sudo cp arch/arm64/boot/Image /mnt/boot/$KERNEL.img
      sudo cp arch/arm64/boot/dts/broadcom/*.dtb /mnt/boot/
      sudo cp -r arch/arm64/boot/dts/overlays/* /mnt/boot/overlays/
      ```

### 2.3. 실시간(RT) 커널 패치 및 컴파일

1.  **RT 패치 다운로드 및 적용**:
    ```bash
    wget https://mirrors.edge.kernel.org/pub/linux/kernel/projects/rt/6.6/patch-6.6.78-rt52-rc1.patch.gz
    gunzip *.gz
    patch -p1 < *.patch
    ```
2.  **RT 커널 설정**:
    - `make menuconfig` 실행: `General setup` → `Preemption Model` → `Fully Preemptible Kernel (Real-Time)` 선택.
3.  **컴파일 및 설치**: 표준 커널과 동일한 과정으로 진행.
4.  **성능 검증**:
    - `uname -r` 명령어로 RT 커널 버전 확인.
    - `cyclictest`로 실시간 성능(최대 지연 시간)을 측정하여 개선 확인.
