## **1. 코드 최적화 기본 개념**

*   **최적화란?**: 동일한 기능을 수행하면서 실행 시간 또는 메모리 사용량을 줄이는 것.
*   **최적화 주체**:
    *   **컴파일러**: `-O0, -O1, -O2, -O3` 같은 최적화 레벨 옵션을 통해 자동으로 코드 최적화. 레벨이 높을수록 공격적이지만, 디버깅이 어려워짐.
        *   `-O0`: 최적화 없음 (디버깅용)
        *   `-O1`: Dead Code 제거, Constant Folding 등 기본 최적화
        *   `-O2`: 루프 전개(Unrolling), 함수 인라인 등 적극적 최적화 (릴리즈용)
        *   `-O3`: 실행 속도 극대화를 위한 모든 기법 적용
    *   **사용자 (프로그래머)**: 코드 작성 단계에서 직접 최적화 기법을 적용.
*   **최적화의 필요성**: 임베디드 시스템은 PC와 달리 CPU, RAM, ROM 등 자원이 제한적이므로, 한정된 자원 내에서 원하는 기능을 구현하기 위해 최적화가 필수적.
*   **메모리 구조**:
    *   **PFlash (ROM)**: `.text`(코드), `.data`(초기화된 전역/정적 변수) 저장.
    *   **RAM**: `.data` (ROM에서 복사), `.bss`(초기화되지 않은 변수), `heap`(동적 할당), `stack`(지역 변수, 함수 인자)으로 구성.
*   **데이터 타입과 지정자**:
    *   **Native Data Type**: 프로세서가 가장 효율적으로 처리하는 데이터 타입(예: TriCore에서 32bit `int`)을 사용하는 것이 속도에 유리.
    *   **지정자(Specifier)**: `static`, `extern`, `register`, `const`, `volatile` 등은 변수의 저장 위치, 생명주기, 접근 방식을 결정하며 최적화의 핵심 요소.
        *   `volatile`: 컴파일러의 최적화를 막고 항상 메모리에서 값을 읽고 쓰도록 강제. (하드웨어 레지스터 접근 시 필수)
        *   `const`: 값이 변하지 않음을 명시하여 ROM에 데이터를 저장하고 RAM 낭비를 막는 데 사용 가능.

## **2. 최적화 성능 분석 실습**

*   **개발 환경**:
    *   **IDE**: Aurix Development Studio (Infineon TriCore용)
    *   **Debugger**: UDE (Universal Debug Engine)
*   **실습 과정**:
    1.  개발 도구 설치 및 프로젝트 생성/가져오기.
    2.  TC375 타겟 보드 연결 및 설정.
    3.  프로그램 빌드 및 보드에 다운로드.
    4.  UDE 디버거를 이용한 프로그램 실행 및 분석.
*   **디버거 활용**:
    *   **주요 View**: Disassembly (어셈블리 코드 확인), Memory (메모리 상태 확인), Peripheral Registers (하드웨어 레지스터 접근) 등을 통해 최적화 전후의 코드 변화와 성능을 직접 눈으로 확인.
    *   **STM 타이머 실습**: STM(System Timer) 모듈을 이용해 코드 실행 시간을 나노초(ns) 단위로 정밀하게 측정하는 타이머를 구현하여 각 최적화 기법의 성능 향상 정도를 정량적으로 분석.

## **3. 최적화 방법**

**1) 전역/지역 변수 최적화**
*   **전역 변수**: 메모리에 직접 접근해야 하므로 느림. 루프 안에서 반복적으로 사용할 경우, 루프 시작 전에 지역 변수에 복사해 사용하고 루프 종료 후 다시 전역 변수에 저장하면 성능 향상.
*   **지역 변수**: `register` 키워드를 사용해 레지스터에 할당을 유도하면 더 빠름.

**2) 데이터 구조 최적화**
*   **Data Alignment (데이터 정렬)**: `struct`(구조체)의 멤버를 크기가 큰 순서대로 배치하여 메모리 패딩(padding)을 최소화하고, 메모리 사용량을 줄임.
*   **`switch` vs. `if-else`**:
    *   `if-else`는 조건이 복잡하거나 범위 비교에 유리.
    *   `switch`는 case가 많고 연속적인 정수일 때, 컴파일러가 `jump table`로 최적화하여 매우 빠른 분기 처리 가능.
*   **배열과 포인터**: 배열 인덱스를 이용한 `switch`문은 분기 및 비교 연산을 제거하여 성능을 높일 수 있음 (예: 함수 포인터 배열).
*   **`union` (공용체)**: 메모리를 공유하는 특성을 이용해 여러 데이터를 한 번의 연산으로 처리하여 최적화 가능.

**3) 메모리 최적화 (ROM & RAM)**
*   **ROM 최적화 (코드 크기 줄이기)**:
    *   `printf`와 같은 거대한 표준 라이브러리 함수 사용 자제.
    *   Dead Code(사용되지 않는 코드) 제거.
    *   상수/전역 변수 대신 지역 변수 사용.
*   **RAM 최적화 (주로 스택 사용량 줄이기)**:
    *   깊은 함수 호출 지양 (스택 오버플로우 방지).
    *   크기가 큰 구조체/배열은 포인터(call by reference)로 전달.
    *   `bit-field`를 사용해 여러 개의 플래그(flag)를 하나의 변수에 저장.
    *   값이 변하지 않는 전역 변수는 `const`로 선언해 RAM에 복사되지 않도록 함.

**4) 함수 최적화**
*   **`inline` 함수**: 함수 호출 오버헤드를 제거하여 속도를 높이지만 코드 크기는 증가. 간단한 함수에 효과적.
*   **재귀 함수**: 스택 소모가 크므로 `for`, `while` 같은 반복문으로 변경하는 것이 유리. (꼬리 재귀 최적화는 특정 조건에서만 가능)
*   **Lookup Table (참조 테이블)**: 반복적이고 복잡한 연산(예: 삼각함수, 팩토리얼)의 결과를 미리 계산하여 배열에 저장해두고, 필요할 때 찾아 쓰는 방식. 속도가 매우 빠름.
*   **함수 인자**: 인자 개수는 4개 이하로 유지 (초과 시 스택 사용). 인자의 데이터 타입은 Native Type 사용.

**5) 루프 최적화**
*   **Loop Unrolling (루프 풀기)**: 루프의 반복 횟수를 줄여 분기 오버헤드를 감소.
*   **Loop Fusion (루프 병합)**: 인접한 두 루프를 하나로 합쳐 오버헤드 감소.
*   **Loop Invariant (루프 불변식)**: 루프 내에서 변하지 않는 계산은 루프 밖으로 이동.
*   **루프 변수**: `register int`와 같이 선언하고, 0과 비교하는 방식(N에서 0으로 감소)이 더 효율적.

**6) 제어 흐름 및 연산 최적화**
*   **연산자 비용**: `비트 연산 << 덧셈/뺄셈 << 곱셈 << 나눗셈` 순으로 빠름. 가능한 한 비용이 낮은 연산자 사용 (예: `* 8` 대신 `<< 3`).
*   **Short-circuit 평가**: `&&`, `||` 연산 시, 결과가 빨리 결정될 확률이 높은 조건을 앞에 배치.
*   **실수(Floating-point) 연산**: 속도가 매우 느리므로 가급적 피하고, 정수형 연산(고정 소수점)으로 대체.
