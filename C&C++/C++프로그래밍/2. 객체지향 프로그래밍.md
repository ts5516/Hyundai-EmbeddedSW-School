# 객체 지향 프로그래밍

## 객체 지향 프로그래밍(OOP)의 정의

- 현실 세계를 구성하는 객체들의 개념을 소프트웨어로 표현
- 각 객체는 고유의 데이터(속성)와 행동(메서드)을 가진다
- 프로그램 전체를 여러 객체로 구성하고, 객체 간의 **메시지 전달**로 프로그램이 동작

```cpp
class 구매자 { };

class 판매자 { };

class 붕어빵 {
private:
	int 원가;

public:
	int paste;          // 팥, 슈크림, 초코, 딸기
	int 소비자가격;
	int xxx;
	int yyy;
	std::string name;

	void addPaste(int paste) {
		this->paste += paste;
	}
};

class 강아지 {
	std::string name;
	int age;
	bool gender;

	void run() { }
	void walk() { }
	void bark() { }
};
```

---

## 객체란 무엇인가?

* **데이터(속성, 상태)** + **행동(메서드, 행동)** 를 하나로 묶은 단위
* 예: 자동차 객체

  * 속성: 색상, 속도
  * 행동: 달리기(run), 멈추기(stop)
* 프로그램은 여러 객체가 **서로 메시지를 주고받으며 동작**한다.

---

## OOP의 핵심 개념 4가지

### 1. 추상화 (Abstraction)

* 실제 객체의 중요한 특징만 **추출하여 소프트웨어로 표현**하는 것
* 불필요한 정보는 숨기고, **본질적인 속성과 동작만 표현**

### 2. 캡슐화 (Encapsulation) + 정보 은닉 (Information Hiding)

* 데이터(속성)와 메서드(함수)를 하나의 객체로 묶는다.
* 외부에서 직접 접근하지 못하도록 보호(정보 은닉)
* **복잡한 내부 구현은 숨기고**, 필요한 기능만 외부에 공개
* 예시: 자동차 운전자는 핸들과 페달만 조작, 엔진 내부 구조는 몰라도 됨.

### 3. 상속 (Inheritance)

* 기존 클래스(부모)의 속성과 메서드를 새로운 클래스(자식)가 **물려받아 재사용**하는 것
* 코드 재사용성과 확장성 증가
* 계층적 구조 설계 가능

### 4. 다형성 (Polymorphism)

* 동일한 이름의 메서드가 **객체 타입에 따라 다르게 동작**할 수 있음
* 예: `draw()` 메서드는 도형에 따라 다르게 구현 가능 (오버라이딩)

  * 원: 원을 그리는 동작
  * 사각형: 사각형을 그리는 동작

## 절차 지향 언어 vs 객체 지향 언어 비교

| 구분 | 절차 지향 언어 (Procedural) | 객체 지향 언어 (Object-Oriented) |
|------|-----------------------------|----------------------------------|
| 중심 개념 | 함수(절차), 순차적 처리 | 객체, 클래스, 메시지(메서드) |
| 프로그램 구조 | 함수(프로시저)들의 모임, 순서가 중요 | 객체(클래스)들의 상호작용 |
| 데이터와 코드 | 분리됨 | 객체 안에 캡슐화됨 |
| 데이터 접근 | 전역/지역 변수 사용 | 메서드를 통한 데이터 접근 |
| 재사용성 | 낮음 (코드 복사 중심) | 높음 (상속, 다형성, 캡슐화 활용) |
| 유지보수 | 어려움 (수정 영향 범위 큼) | 쉬움 (객체 단위로 수정 가능) |
| 확장성 | 낮음 (전체 코드 수정 필요) | 높음 (새로운 객체/클래스 추가 용이) |
| 실행 속도 | 빠른 편 (단순 구조) | 상대적으로 느릴 수 있음 (추상화 오버헤드) |
| 대표 언어 | C, Pascal, Fortran | C++, Java, Python, C#, Swift |
| 예시 | C 함수 중심 프로그램 | Java의 클래스/객체 중심 프로그램 |

## 샘플 코드 비교

### 절차 지향 언어 (C 예시)

```c
void tiger(void) {
	// code here...
}
void lion(void) {
	// code here...
}
void elephant(void) {
	// code here...
}
````

* **함수 중심**으로 동작.
* 데이터와 함수가 별도로 존재.

### 객체 지향 언어 (C++ 예시)

```cpp
class Tiger {
	// code here...
};

class Lion {
	// code here...
};

class Elephant {
	// code here...
};
```

* **객체 중심**으로 동작.
* 데이터(속성)와 기능(메서드)가 함께 묶인다.

---

## 절차 지향 언어의 특징

* 순차적 처리와 함수 호출에 집중
* 데이터와 함수가 분리됨
* 전역/지역 변수를 통해 데이터 공유
* 프로그램 흐름(절차)이 중요
* 장점: 빠른 실행 속도, 하드웨어 친화적
* 단점: 유지보수, 재사용, 확장성에 한계가 있음
  (코드 중복, 전역 변수 남용, 대규모 프로젝트에 부적합)

---

## 객체 지향 언어의 특징

* 현실 세계의 객체를 소프트웨어로 모델링
* 데이터(속성)와 기능(메서드)가 객체로 캡슐화됨
* 상속, 다형성, 캡슐화로 코드 재사용과 확장성 높음
* 객체 간 메시지(메서드 호출)로 상호작용
* 장점: 유지보수, 확장성, 재사용성 우수
* 단점: 구조가 복잡해지고 실행 속도가 다소 느릴 수 있음

## 클래스의 기본 문법과 구조

클래스는 **추상화된 사용자 정의 데이터 타입**이다.  
구조체(struct)와 유사하지만 `class` 키워드를 사용하며, 기본 접근 지정자는 `private`이다.

```cpp
class 클래스이름 {
	멤버_변수_데이터_타입 멤버_변수명;
	멤버_함수_선언 또는 정의;
};
````

### 예시

```cpp
class Foo {
public:
	int a; // 멤버 변수
	int b;

	void func1() {} // 멤버 함수
	void func2() {}
};
```

## 용어 정리

### 클래스 vs 인스턴스

* **클래스**: 설계도, 메모리에 존재하지 않음
* **인스턴스(객체)**: 클래스 기반으로 메모리에 생성된 실체

### 멤버 변수의 다양한 명칭

* 데이터, 멤버 데이터, 멤버, 필드, 속성, 멤버 변수

### 멤버 함수의 다양한 명칭

* 메서드, 멤버 함수

---

## 클래스 사용 예

```cpp
int main() {
	Foo foo; // 인스턴스 생성
	foo.a = 11;
	foo.b = 22;
}
```

비유:

* 붕어빵틀 = 클래스
* 붕어빵 = 인스턴스

# 상수 멤버 함수 (const member function)

---

## const 객체

상수 객체는 내부 상태를 변경할 수 없는 객체이며, **상수 멤버 함수만 호출 가능**하다.

```cpp
const Point p2(1, 2);
```

```cpp
void print() const {
	std::cout << x << "," << y << std::endl;
}
```

### 왜 필요한가?

* const 참조 파라미터를 사용할 때 반드시 const 멤버 함수 호출 필요

```cpp
void foo(const Rect& r) {
	int area = r.getArea(); // getArea()가 const 멤버 함수여야 함
}
```

### 좋은 사용 습관

* 상태 변경 없는 함수는 반드시 **const 멤버 함수**로 작성
* 예: getter 함수는 항상 const 멤버 함수로 작성

```cpp
int getArea() const { return (w * h); }
```

# 클래스 내 static 변수(클래스 변수) 및 static 함수

---

## 클래스 변수란?

클래스 내의 `static` 변수는 **정적 멤버 변수 또는 클래스 변수**라고 한다.
클래스 변수는 **인스턴스 없이 클래스명으로 직접 접근 가능**하다.

```cpp
class Foo {
public:
	static int x;

	static void sfunc1() {
		std::cout << "sfunc1()" << std::endl;
	}
};

int Foo::x = 12; // 정적 변수 초기화
```

```cpp
Foo::x = 33;
Foo::sfunc1();
```

---

## 멤버 변수 vs 클래스 변수

* **멤버 변수**: 각 인스턴스마다 별도로 존재
* **클래스 변수**: 클래스 전체에서 공유됨, 인스턴스가 없어도 접근 가능

---

## 예시: 붕어빵 몇 개 만들어졌는지 세기

```cpp
class Fishbun {
public:
	int cnt1;           // 인스턴스별로 개별 존재
	static int cnt2;    // 클래스 전체에서 공유

	Fishbun() : cnt1{0} {
		++cnt1;
		++cnt2;
	}
};

int Fishbun::cnt2 = 0;
```

```cpp
Fishbun f1;
std::cout << f1.cnt1 << "," << Fishbun::cnt2 << std::endl;

Fishbun f2;
std::cout << f1.cnt1 << "," << Fishbun::cnt2 << std::endl;

Fishbun f3;
std::cout << f1.cnt1 << "," << Fishbun::cnt2 << std::endl;
```

* `cnt1`은 각 인스턴스별로 존재 (항상 1)
* `cnt2`는 클래스 전체에서 공유 → 붕어빵 총 개수 카운트 가능

# 클래스 핵심 개념 정리 흐름

1. **클래스와 인스턴스**

   * 클래스는 설계도
   * 인스턴스는 메모리에 생성된 객체

2. **멤버 변수와 멤버 함수**

   * 멤버 변수 = 데이터
   * 멤버 함수 = 동작

3. **상수 멤버 함수**

   * const 객체는 const 멤버 함수만 호출 가능
   * 상태 변경 없는 함수는 const 멤버 함수로 작성

4. **클래스 변수와 클래스 함수**

   * static 변수(클래스 변수)는 클래스 전체에서 공유
   * static 함수는 클래스명으로 호출 가능
   * 인스턴스 없이도 사용 가능

---

이 구조를 기반으로 이후 클래스 심화 개념(생성자/소멸자, 접근 지정자, static 멤버 함수 활용, const 객체 활용 등)을 이어서 학습하면 된다.

## 상속관계에서 생성자, 소멸자 호출

## 하위 객체 생성 시 상위 객체 생성자 호출

하위 객체가 생성될 때 상위 객체의 생성자도 함께 호출된다.  
기본적으로 **상위 클래스의 기본 생성자**가 호출된다.  
만약 상위 클래스에 오버로딩된 생성자가 필요하면 명시적으로 호출해야 한다.

```cpp
class 아빠 {
public:
	아빠() { std::cout << "아빠() 호출" << std::endl; }
	아빠(int a) { std::cout << "아빠(int) 호출" << std::endl; }
	~아빠() { std::cout << "~아빠() 호출" << std::endl; }
};

class 딸 : public 아빠 {
public:
	딸() { std::cout << "딸() 호출" << std::endl; }
	딸(int b) { std::cout << "딸(int) 호출" << std::endl; }
	~딸() { std::cout << "~딸() 호출" << std::endl; }
};
````

```cpp
딸 예림;      // 호출 순서: 아빠() → 딸()
딸 예슬(11);  // 호출 순서: 아빠() → 딸(int)
```

**객체 생성 시**: 부모 → 자식 순서로 생성
**객체 소멸 시**: 자식 → 부모 순서로 소멸

---

## 상속관계에서 상위 객체 생성자 호출 시 주의사항

상위 클래스에 **기본 생성자**가 없고 오버로딩된 생성자만 있는 경우, 하위 클래스에서 반드시 명시적으로 상위 생성자를 호출해야 한다.

```cpp
class Person {
public:
	std::string name;
	int age;

	Person(const std::string& name, int age) : name{ name }, age{ age } {}
};
```

```cpp
class Student : public Person {
public:
	std::string major;
	int number;

	Student(std::string major, int number, std::string name, int age)
		: Person{ name, age }, major{ major }, number{ number } {}
};
```

```cpp
Student s1 = { "컴퓨터공학", 92, "홍길동", 20 };
```

* Person 클래스에 기본 생성자가 없으므로 반드시 `Person{ name, age }` 형식으로 호출해야 한다.
* 그렇지 않으면 컴파일 에러 발생.

---

## 기반 클래스의 소멸자는 반드시 가상으로 만들어야 한다

### 정상적인 경우

```cpp
class Base {
public:
	Base() { std::cout << "Base()" << std::endl; }
	~Base() { std::cout << "~Base()" << std::endl; }
};

class Derived : public Base {
public:
	Derived() { std::cout << "Derived()" << std::endl; }
	~Derived() { std::cout << "~Derived()" << std::endl; }
};
```

```cpp
Derived* d = new Derived();
delete d; // 호출 순서: ~Derived() → ~Base()
```

### 업캐스팅 후 문제가 발생할 수 있는 경우

```cpp
Base* b2 = new Derived();
delete b2;
```

* Base의 소멸자가 **가상 함수가 아니면** Derived의 소멸자가 호출되지 않는다.
* 자식 클래스에서 동적 자원을 해제하는 코드가 있다면 **메모리 누수 발생 가능**.

### 해결 방법

```cpp
class Base {
public:
	virtual ~Base() { std::cout << "~Base()" << std::endl; }
};
```

* **가상 소멸자(virtual destructor)** 를 선언하여 업캐스팅 후 delete 시에도 파생 클래스의 소멸자가 정상 호출되도록 해야 한다.

---

## 주의사항 요약

* 하위 객체 생성 시 상위 객체의 생성자도 반드시 호출된다 (기본 생성자 또는 명시적 호출 필요).
* 상위 클래스에 기본 생성자가 없으면, 하위 클래스에서 명시적으로 상위 생성자를 호출해야 한다.
* **가상 소멸자**를 사용하여 업캐스팅된 포인터로 delete 시 자식 클래스 소멸자가 호출되도록 보장해야 한다.

---

## 정적 바인딩과 동적 바인딩의 핵심

- **정적 바인딩**
    - 일반적인 함수는 정적 바인딩.
    - **컴파일 시점에 호출할 함수가 결정**된다.
    - 포인터의 자료형을 기준으로 판단, 실제 객체 타입은 고려하지 않는다.

- **동적 바인딩**
    - **가상 함수(virtual)** 가 선언된 경우 적용된다.
    - **실행 시점(런타임)에 호출할 함수가 결정**된다.
    - 실제 객체 타입에 따라 오버라이딩된 함수가 호출된다.

## 정적 바인딩 예제

```cpp
class 할아버지 {
public:
	void writeBook() {
		cout << "박지원 할부지가 책을 써요." << endl;
	}
};

class 아버지 : public 할아버지 {
public:
	void writeBook() {
		cout << "박종채 아버지가 책을 써요." << endl;
	}
};

class 아들 : public 아버지 {
public:
	void writeBook() {
		cout << "박규수 아드님이 책을 써요." << endl;
	}
};
````

```cpp
할아버지* 박지원 = new 아버지();
아버지* 박종채 = new 아들();

박지원->writeBook(); // 박지원 할부지가 책을 써요.
박종채->writeBook(); // 박종채 아버지가 책을 써요.
```

* 포인터의 **자료형 기준으로 함수가 호출**됨.
* 업캐스팅 후에도 포인터 타입의 함수가 호출됨.

---

## 동적 바인딩 예제

```cpp
class 할아버지 {
public:
	virtual void writeBook() {
		cout << "박지원 할부지가 책을 써요." << endl;
	}
};

class 아버지 : public 할아버지 {
public:
	virtual void writeBook() override {
		cout << "박종채 아버지가 책을 써요." << endl;
	}
};

class 아들 : public 아버지 {
public:
	virtual void writeBook() override {
		cout << "박규수 아드님이 책을 써요." << endl;
	}
};
```

```cpp
할아버지* 박지원 = new 아버지();
아버지* 박종채 = new 아들();
아들* 박규수 = new 아들();

박지원->writeBook(); // 박종채 아버지가 책을 써요.
박종채->writeBook(); // 박규수 아드님이 책을 써요.
박규수->writeBook(); // 박규수 아드님이 책을 써요.
```

* 가상 함수(virtual)가 선언된 경우, **실제 객체의 타입에 따라 함수 호출**.
* 업캐스팅 후에도 **실제 객체 타입 기준으로 함수가 호출**됨.

---

## 핵심 개념

* 일반 함수 → 정적 바인딩 (컴파일 시점에 결정)
* 가상 함수 → 동적 바인딩 (실행 시점에 결정, 다형성(polymorphism) 지원)
* 동적 바인딩을 통해 상속 관계에서 유연한 함수 호출 가능 (업캐스팅에 유리)

```cpp
Base* p = new Derived();
p->virtualFunction(); // 동적 바인딩으로 Derived의 함수 호출
```
