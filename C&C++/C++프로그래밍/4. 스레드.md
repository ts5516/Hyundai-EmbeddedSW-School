# 프로세스와 스레드 (Process vs Thread)

---

## 1. 프로그램 vs 프로세스

| 구분       | 설명 |
|------------|------|
| 프로그램   | 실행 가능한 명령어들의 집합 (예: 디스크에 저장된 EXE 파일) |
| 프로세스   | 메모리에 적재되어 실행 중인 프로그램. 운영체제로부터 자원(CPU, 메모리 등)을 할당받음 |

---

## 2. 프로세스 vs 스레드

### 프로세스(Process)

- 운영체제로부터 **독립된 자원(메모리 공간)**을 할당받아 실행되는 단위
- **각자 코드, 데이터, 힙, 스택을 보유**
- 다른 프로세스와 자원 공유 불가 → **IPC 필요**
- 생성/소멸 시 **오버헤드 큼**

### 스레드(Thread)

- 프로세스 내부에서 동작하는 **작업의 흐름**
- **코드, 데이터, 힙은 공유**, 스택은 독립
- 같은 프로세스 내에서 자원 공유
- 생성/전환이 빠르나 **경쟁 조건** 및 **데드락** 우려 있음

---

## 3. 비교 요약

| 구분 | 프로세스 | 스레드 |
|------|----------|--------|
| 메모리 공간 | 독립 | 공유 (힙, 데이터) |
| 통신 방식 | IPC 필요 | 공유 메모리로 간단 |
| 생성 비용 | 큼 | 작음 |
| 종료 영향 | 독립 | 하나가 죽으면 프로세스 전체 영향 가능 |

---

## 4. 멀티 프로세스 vs 멀티 스레드

### 멀티 프로세스

- 여러 개의 프로세스를 운영
- 각각 독립 메모리 사용 → 안정적
- **IPC 필요**, 오버헤드 큼

### 멀티 스레드

- 하나의 프로세스 내에서 여러 스레드 실행
- 자원 공유로 효율적
- **동기화 필요**, 관리 어려움

---

## 5. 프로세스 상태 (스레드와 유사)

| 상태 | 설명 |
|------|------|
| New | 프로세스 생성 시작 |
| Ready | CPU 할당 대기 중 |
| Running | CPU 점유하여 실행 중 |
| Waiting | 입출력 등 외부 이벤트 대기 중 |
| Terminated | 실행 종료 및 자원 반납 |

상태 전이 예시:

- **Ready → Running** : 스케줄러가 CPU 할당
- **Running → Waiting** : 입출력 발생
- **Waiting → Ready** : 입출력 완료
- **Running → Terminated** : 실행 종료

---

## 6. IPC (Inter-Process Communication)

### 개념

- 서로 다른 프로세스 간에 데이터 교환 및 동기화를 위한 메커니즘

### 방식

| 방식 | 설명 |
|------|------|
| 파이프(Pipe) | 단방향 데이터 전달 |
| 메시지 큐(Message Queue) | 메시지 형태로 통신 |
| 공유 메모리(Shared Memory) | 메모리 영역을 공동 사용 |
| 소켓(Socket) | 네트워크 기반 통신 |
| 세마포어(Semaphore) | 동기화 및 접근 제어 |

### 특징

- **장점**: 효율적인 데이터 전달, 병렬 작업 수행
- **단점**: 구현 복잡, 동기화 이슈, 성능 관리 필요

# 스레드 동기화와 데드락

---

## 1. 스레드 동기화란?

멀티스레드 환경에서 여러 스레드가 동시에 공유 자원(메모리, 파일 등)에 접근할 때 **충돌이나 데이터 불일치**를 방지하는 기법.

### 목적

- 작업 순서 제어
- 데이터 무결성 보장
- Race Condition 방지
- 데드락 방지

---

## 2. 동기화가 필요한 이유

1. **데이터 무결성**
   - 동시 접근 시 데이터 오염 가능
   - 예: 은행 계좌에서 동시에 출금

2. **Race Condition 방지**
   - 작업 순서가 꼬여 잘못된 연산 발생

3. **Deadlock 방지**
   - 스레드 간 자원 대기 상태로 무한 대기 가능

4. **작업 순서 제어**
   - 중요한 연산이 순서대로 처리되도록 보장

---

## 3. 데드락 (Deadlock)

### 정의

둘 이상의 스레드가 서로 자원을 점유한 채, 상대방의 자원을 기다리며 **무한 대기 상태**에 빠지는 현상.

---

## 4. 데드락 예제 코드

```cpp
void worker1(int& counter, std::mutex& m1, std::mutex& m2) {
    m1.lock();
    m2.lock();
    counter += 1;
    m2.unlock();
    m1.unlock();
}

void worker2(int& counter, std::mutex& m1, std::mutex& m2) {
    m2.lock();
    m1.lock();
    counter += 1;
    m1.unlock();
    m2.unlock();
}
````

### 데드락 발생 조건

| 조건     | 설명                           |
| ------ | ---------------------------- |
| 상호 배제  | 하나의 자원은 한 번에 하나의 스레드만 사용 가능  |
| 점유와 대기 | 자원을 점유한 상태에서 다른 자원을 기다림      |
| 비선점    | 다른 스레드가 점유한 자원을 강제로 빼앗을 수 없음 |
| 순환 대기  | 스레드들이 자원을 순환적으로 기다림          |

---

## 5. 해결 방법

### 방법 1. **락 순서 통일**

```cpp
// 항상 m1 → m2 순서로 락
m1.lock();
m2.lock();
// 작업
m2.unlock();
m1.unlock();
```

모든 스레드가 **동일한 순서로 락을 획득**하도록 하면 데드락 방지 가능.

---

### 방법 2. **lock\_guard 사용**

```cpp
std::lock_guard<std::mutex> lock1(m1);
std::lock_guard<std::mutex> lock2(m2);
```

RAII 방식으로 예외가 발생해도 락이 안전하게 해제됨.

---

### 방법 3. **std::scoped\_lock 사용 (C++17 이상)**

여러 락을 **한 번에 획득**하여 데드락 방지

```cpp
std::scoped_lock lock(m1, m2);
```

---

## 6. 결론

* 멀티스레드 환경에서의 동기화는 **필수**
* 데드락 방지를 위해 락 획득 순서를 일관되게 유지하거나 `lock_guard`, `scoped_lock` 등의 도구를 사용하는 것이 안전함
