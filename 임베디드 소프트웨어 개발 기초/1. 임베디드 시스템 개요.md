## 임베디드 시스템 vs 범용 시스템
- 임베디드시스템 (내장형 시스템)
    - 특정 목적을 수행하기 위한 컴퓨터 시스템
        - 특정 목적에만 수행하기 때문에, 목적에 맞는 기능만 개발함
        - 목적에 따라 요구되는 HW, SW 성능 및 기능이 상이함
        - 목적에 따라 실시간 운영체제 또는 운영체제를 사용하지 않을 수 있음
- 범용시스템
    - 다양한 용도로 사용하기 위해 개발된 컴퓨터 시스템
        - 다양한 용도롤 사용하기 때문에 다양한 sw를 사용할 수 이씨도록 개발됨

- 시스템 : 어떤 목적이나 기능을 달성하기 위해 서로 관련된 요소들이 유기적으로 구성된 직합

## 차량 임베디드 시스템의 역할
- 옛날에는 다 기계로만 했다
- 1970년대 부터 임베디드 시스템이 도입되기 시작했다.
- 현재는 전기차 및 sdv 확대
    - sdv(software defined vehicle) 도입 - 차량 기능 및 성능을 결정하는 요소가 소프트웨어 중심으로 도입

## 차량 제어기 특징
- 무게 및 크기가 작고 저렴해야 함
- 연비를 위해 저전력이 필요함

### SoC(System on Chip) 기반 MCU
- CPU 및 메인보드에 내장된 컴퓨터 동작에 필요한 필수 기능을 하나의 SoC로 개발함
- 제어기는 MCU가 제공하지 않는 전원 및 아날로그 신호 관련 회로 등이 추가 장착됨
- 대표적인 MCU로 TC375가 있다. 자동차 업계에서 실제로 많이 쓰인다.
- MCU 구조 : Cpu, memory, peripheral module
## 디지털 컴퓨터 하드웨어 구성
- 중앙처리장치 (CPU), RAM(Randon Access Memory), 입출력장치(IOP)

### 명령어 사이클
1. 명령어를 메모리에서 가져온다 Fetch
2. 명령어를 디코딩 한다.
3. 간접 주소 방식의 명령어일 경우 메모리에서 유효 주소 읽어 온다
4. 명령어를 실행한다.

#### Fetch
- PC에서 저장된 주소에서 명령어을 읽어 IR에 저장함
- 메모리에서 현재 실행할 명령어를 가져온다.

#### 컴퓨터 명령어 형식
- 메모리 참조 명령어, 레지스터 참조 명령어, 입출력 명령어

### 명령어 집합 구조(ISA)
- isa(instrcution set architecture) : cpu가 인식하여 실행할 수 있는 기계어 명령어 집합
- 명령어 구조는 isa 별로 차이가 있다는 정도만 알아두자

## 어셈블리어
- 기계어를 symbol로 변환해 놓음, 사람이 이해가기 용이하게

## 고급 언어
- 컴파일러에 의해 어셈블리 언어로 변환

## 프로그래밍 과정
- 고급 언어로 코딩된 프로그램
    - 컴파일러에 의해 어셈블리 언어로 변환
    - 어셈블러에 의해 오브젝트 코드로 변환
    - 링커에 의해 주소 변환 후 실행 파일 생성됨


## Peripheral Module
- CPU는 외부 모듈의 메모리에 원하는 Data를 R/W함
- CPU가 어떤 모듈을 쓰고 싶을 때는 Bus를 통해서 메모리에 있는 레지스터에 값을 1로 바꾸면 GPIO회로를 통해 해당 모듈을 동작한다
- CPU 가 실제로 메모리맵을 가지고 버스를 통해 특정 모듈을 동작하게끔 명령을 내릴 수 있다.

### General-Purpose Input/Output(GPIO) 회로
GPIO 회로는 GPIO 핀을 연결해서 CPU와 모듈을 연결

즉, 단순히 MCU나 CPU 칩 안의 설정만이 아니라, GPIO 핀에 전기적인 회로를 연결해서 실제 하드웨어 동작을 만드는 걸 말해.

## 메모리 맵
- 칩 샐렉트를 사용해서 메모리 번지와 ic칩을 매핑해놓는다.
- 내가 원하는 모듈을 접근하기 위해 해당 매핑테이블을 보고 접근할 수 있다.

## 프로그램 인터럽트
- CPU가 주기적으로 입출력 장치의 상태를 체크
- Polling 방식이라 부름
- Polling 방식의 CPU 자원 낭비 문제 개선을 위해 개발
- HW에 의해 입/출력 이벤트가 발생하면, 특정 프로그램 수행

### 인터럽트 사이클 순서도
- 명령 사이클 수행 시 인터럽트 이벤트 발생 여부 확인
- 다음 명령 사이클 시작 시 인터럽트 발생 플래그(R)이 Set되어 있으면 인터럽트 사이클 수행

### 인터럽트 사이클 수행 과정
벡터테이블에 있는 ISR을 통해 실제 인터럽트 루틴 시작 주소로 이동한다.

## Interrupt vs Exception vs trap
- 하던일 을 멈추고 별도의 service routine을 실행하는 것은 동일, 세브 정의는 cpu 제조사마다 차이가 있음

### exception : cpu 내부에서 발생, 예외적인 상황으로 인해 발생

### interrupt : 외부 i/o 장치 등에서 발생, 비동기적으로 발생

### trap : 일반적으로 sw interrupt를 trap이라 함

## MPU(Micro Process Unit)
- 고성능 코어와 관련 모듈이 하나의 soc로 구성
- flash 및 ram은 포함하지 않음

### NXP S32G3 시리즈
게이트웨이를 위한 MPU 시리즈
- 리눅스 동작 가능한 MPU 및 실시간 기능 동작을 위한 MCU 내장

## MCU vs MPU
- mcu : 실시간 제어 중심
    - 단일 칩 형태로 저렴하게 실시간 제어 가능
- mpu : 고성능 데이터 처리 중심
    - 멀티코어 cpu와 고급 운영체제를 통해 복잡한 연산 및 데이터 처리 수행

## 반도체 메모리
- 반도체 메모리: 반도체의 회로를 전기적으로 제어하여 데이터를 기억 및 저장하는 장치
    - 휘발성(RAM), 비휘발성(ROM)

## 반도체 메모리 특징
- SRAM이 DRAM에 비해 훨씬 R/W가 빠르다. 하지만 비싸다
- ROM flash를 많이쓴다. 저렴하고 대용량화 하기도 좋아서

### NAND Flash vs NOR Flash
NOR flash : 데이터 읽는 용도
NAND flash : 데이터 저장 용도

## 메모리 계층 구조
- 캐시 < 메인메모리(RAM) < 외부메모리
- 단위 용량당 비용 순으로 계층적 구조를 가짐

## 케시메모리
- 메인 메모리와 CPU의 성능 차이를 극복하기 위해 CPU내에 장착되는 고속의 메모리
- cpu 면적의 30~70% 캐시 메모리가 차지

## 데이터 접근 순서
캐시 적중 시 : cpu는 캐시에서 데이터 가져와 사용
캐시 미스, 메모리 적중 : 주기억장치에서 데이터를 가져와 캐시에 저장
캐시 미스, 메모리 미스: 보조에서 가져와 주기억 저장 그리고 다시 캐시에 저장

## 참조의 국한성
- 전형적인 프로그램에서 주어진 시간 동안 메모리 참조는 국한된 영역에서만 이루어지는 경향이 있음
- 90/10 규칙 : 경험적으로 90% 실행시간을 10%코드가 소비

## 메모리 구조
- PMI : Program Memory Interface, 실제 프로그램 코드가 저장되는 영역
- DMI : Data Memory Interface
- DMU  :Data Memory Unit, BootRom, DFlash, PFlash

### BootRom
- MCU 또는 MPU가 전원이 켜졌을 때 가장 먼저 실행하는 초기 코드를 저장하는 메모리 영역
- BootROm에 저장도니 부트로더는 일반적으로 아래 기능을 수행
    - Flash 에 저장된 차량 SW의 검증 및 로딩
    - Flash 리프로그래밍(차량 제어기에 진단기를 연결해서 차량에 있느 Flash에 새로운 프로그램으로 덮어씌운다) 기능

### DFlash(Data Flash)
- 데이터를 저장하기 위해 사용하는 비휘발성 메모리
- 고장코드(DTC), 학습 값, FreezeFrame(Can 통신 오류 정보) 등을 저장
- 코드를 저장하는 PFlash 보다 빈번하게 Write 및 Erase 수행 가능

## ECU(Electromic Control Unit)
- 차량내 다양한 센서 및 통신 정보를 이용하여 액추에이터를 제어하는 전자 제어 장치
- MCU 기반 ECU(실시간 중요하면 사용), AP 기반 고성능 ECU(자율주행 등 고성능 필요하면 사용)

## 자동차 센서

### 센서 정의
- 어떤 물질의 양이나 물체의 움직임(모션센서), 온도, 소리(음성), 조도(광센서), 전자기파 등을 감지하여 측정하는 장치

### 센서의 분류
- 물리량 기반 분류
- 신호 형태 기반 분류
    - 아날로그 센서 : 물리양에 따라 센서의 저항, 전류, 전압 등이 변화하며, 아날로그 값을 직접읽어야 함
    - 디지털 센서 : 물리양은 센서가 아날로그 값을 읽어 디지털로 변환한 후 통신으로 전송

## 자동차 액추에이터

### 차량 액추에이터
- 전기적 신호를 받아 기계적 동작을 수해하는 장치
- 제어 시스템의 명령을 실제 물리적 움직임으로 변환하는 출력 장치

### 분류
- 에너지 소스 기준
    - 전기식(전기 신호), 유압식(기름의 압력), 공압식(공기의 압력), 화약식(화약의 폭발력)
- 동작 방식 기준
    - 회전형(전기 입력 받아 회전), 직선형(모터 회전력을 직선 운동으로 변경)
- 제어 신호 기준
    - CAN(Controller Area Network) : CAN통신 기반으로 출력 신호 입력
    - LIN(Local Interconnect Network) : CAN보다 저렴, 1가닥으로 통신
    - PWM(Pulse Width Modulation)
    - 아날로그 : 전압의 크기
- 기능 복잡도 기준
    - 일반 actuator
    - 스마트 actuator

## 최초의 운영체제
- 최초의 운영체제 GM Operating System(OS)
- 배치 처리가 가능한 GM-NAA I/O
    - 하나의 프로그램이 종료되면 자동으로 그 다음 프로그램을 로딩하여 실행함

## 다중 프로그래밍
- 배치 프로그램의 경우 사용자 입력 또는 출력이 필요한 경우
- 특정 프로그램이 I/O를 기다리고 있는 겨우, 새로운 프로그램을 CPU에서 실행시켜 CPU 사용률을 증가시키기 위해 개발됨
- 다중 프로그램을 위해 메모리 상에 여러 개의 프로그램이 동시에 적재되어야 함

## 시분할 운영체제
- I/O 처리가 발생할 때까지 대기하기 않고, 동시에 실행되는 프로그램을 짧은 시간동안 실행하여 중간 결과를 사용자에게 제공함
- 현재 Linux, Windows 와 같은 범용운영체제가 사용하는 방식
