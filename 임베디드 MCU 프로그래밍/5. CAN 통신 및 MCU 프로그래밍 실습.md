# CAN 통신 및 MCU 프로그래밍 실습

## 1. CAN 제어 프로그래밍

### 1.1. MCMCAN 모듈 (TC37x)

- **주요 기능**:
  - **CAN 2.0 B & CAN FD**: 클래식 CAN(최대 1Mbps)과 CAN FD(최대 5Mbps, 64바이트 데이터) 프로토콜을 모두 지원.
  - **TTCAN**: 하드웨어 기반의 시간 동기화 CAN 통신 지원.
  - **향상된 ID 필터링**: `Message RAM`을 사용하여 수신 메시지를 효율적으로 필터링.
- **모듈 구성**:
  - **CAN Node**: Bosch M_CAN 표준에 따라 구현된 CAN 통신 핵심. 통신 속도, 프레임 처리, 에러 핸들링을 담당.
  - **User Interface**: 클럭 소스 선택, `Message RAM` 관리, 인터럽트 제어 등 사용자 설정을 담당.
- **에러 감지 메커니즘**:
  - **Bit Monitoring**: 송신한 비트와 버스에서 읽은 비트를 비교.
  - **Bit Stuffing**: 5개 연속 동일 비트 전송 시 반대 극성의 비트를 삽입하여 동기화 유지.
  - **Frame Check**: 프레임 형식이 표준에 맞는지 검사.
  - **CRC Check**: 데이터 무결성 검증.
  - **ACK Check**: 수신 노드가 메시지를 정상적으로 받았는지 확인.

### 1.2. CAN 송수신 인터럽트

- **개념**: CAN 메시지 송신 완료 또는 수신 시점에 인터럽트를 발생시켜 CPU가 다른 작업을 하다가 필요할 때만 통신을 처리하는 방식.
- **구현 흐름**:
  1.  **Node 설정**: 송신(TX) 및 수신(RX) 노드의 핀, 통신 속도(Baudrate), 인터럽트 설정을 구성.
  2.  **인터럽트 핸들러 등록**: `IFX_INTERRUPT` 매크로를 사용하여 송/수신 인터럽트 서비스 루틴(ISR)을 등록.
      - **송신 ISR (`CanTxIsrHandler`)**: 송신 완료 시 호출되어 송신 완료 플래그를 클리어하고 LED 점등 같은 후속 작업을 수행.
      - **수신 ISR (`CanRxIsrHandler`)**: 메시지 수신 시 호출되어 `Can_RecvMsg()` 함수로 ID, DLC, 데이터를 읽어오고 처리.
  3.  **주기적 송신**: `main` 함수의 `while` 루프에서 `Can_SendMsg()`를 주기적으로 호출하여 데이터 전송.

### 1.3. CAN ID 필터링

- **목표**: MCU가 처리할 필요가 없는 CAN 메시지를 하드웨어 레벨에서 차단하여 CPU 부하를 줄이는 기능.
- **Mask 필터링 원리**:
  1.  `(수신 ID) XOR (Acceptance ID)`
  2.  `(1번 결과) AND (Acceptance Mask)`
  3.  **최종 결과가 0이면 메시지 수신, 0이 아니면 무시.**
- **활용 함수**:
  - `Can_SetFilterRange(start, end)`: ID가 `start`부터 `end` 범위 내에 있는 메시지만 수신.
  - `Can_SetFilterMask(id, mask)`: `id`와 `mask`를 이용해 특정 비트 패턴을 갖는 ID만 수신.
- **실습 예시**:
  - **0x2xx ID만 수신**: `Can_SetFilterMask(0x200, 0x700)`
    - `0x200` ~ `0x2FF` 범위의 ID만 수신됨.
  - **0x150 ID만 수신**: `Can_SetFilterMask(0x150, 0x7FF)`
    - `0x7FF` 마스크는 ID의 모든 비트를 비교하므로 ID가 `0x150`과 정확히 일치할 때만 수신됨.

## 2. MCU 프로그래밍 실습

### 2.1. 초음파 센서 (HC-SR04)

- **원리 (TOF, Time of Flight)**:
  1.  `Trig` 핀에 10us 이상의 펄스를 보내 초음파를 발사.
  2.  초음파가 물체에 반사되어 돌아올 때까지 `Echo` 핀이 High 상태를 유지.
  3.  `Echo` 핀의 High 상태 유지 시간을 측정.
  4.  **거리 = (시간 × 음속) / 2** 공식으로 거리를 계산 (음속 약 340m/s).
- **구현**:
  - GPT(General Purpose Timer) 모듈을 사용하여 `Echo` 핀의 펄스 폭(시간)을 정밀하게 측정.
- **이동 평균 필터 (Moving Average Filter)**:
  - **목적**: 센서 값의 노이즈나 급격한 변동을 줄여 안정적인 값을 얻기 위함.
  - **원리**: 최근 N개의 데이터를 순환 버퍼에 저장하고, 이들의 평균을 현재 값으로 사용.

### 2.2. 레이저 센서 (TOF Sense)

- **원리**: 근적외선 레이저를 사용하여 TOF 방식으로 거리를 측정. 초음파보다 정밀하고 빠름.
- **주요 특징**:
  - UART 또는 CAN으로 통신.
  - 센서 내장 펌웨어가 거리 계산 후 결과값을 전송.
  - 측정 범위를 벗어나면 신호 세기(`signal_strength`)가 0으로 설정되어 유효하지 않은 값임을 알 수 있음.
- **CAN 프로토콜**:
  - 데이터 필드의 앞 3바이트에 `거리(mm) * 1000` 값이 저장됨.
  - `dis_status`, `signal_strength` 등의 추가 정보를 포함.
- **실습**: CAN 수신 인터럽트에서 레이저 센서의 CAN 프레임을 파싱하여 거리 값을 추출하고, 거리에 따라 LED를 제어.

### 2.3. 블루투스 통신 (HC-05)

- **개념**: UART 통신을 기반으로 동작하는 시리얼-블루투스 변환 모듈.
- **연결**:
  - **PC**: 블루투스 연결 시 가상 COM 포트로 인식됨. `PuTTY` 같은 터미널 프로그램으로 데이터 송수신.
  - **MCU (TC375)**: MCU의 ASCLIN(UART) 모듈과 연결하여 시리얼 통신.
- **AT-Command**:
  - 블루투스 연결이 없는 상태에서 AT 명령어를 전송하여 모듈의 이름(`AT+NAME`), 비밀번호(`AT+PIN`) 등을 설정.
- **실습**:
  - **에코(Echo) 테스트**: PC에서 보낸 문자를 MCU가 블루투스로 수신한 뒤, 그대로 다시 PC로 전송.
  - **LED 제어**: PC에서 '1' 또는 '0'을 보내면 MCU가 이를 수신하여 LED를 켜거나 끔.
  - **모터 제어**: 'w', 's' 키를 입력받아 모터의 듀티 사이클을 조절하여 가/감속 제어.
