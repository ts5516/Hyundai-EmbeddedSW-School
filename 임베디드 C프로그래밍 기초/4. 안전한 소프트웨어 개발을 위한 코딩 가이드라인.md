# MISRA C 실습 및 규칙 정리

---

## 안전한 소프트웨어 개발을 위한 코딩 가이드라인

### Rule vs Directive

* **Rule**: 컴파일러 또는 정적 분석 도구를 통해 자동 검증이 가능한 규칙 (예: typedef 사용 금지, 함수 선언 일치 등)
* **Directive (Dir)**: 문서화나 설계 분석이 필요한 요구사항으로, 정적 분석으로는 확인이 어려움 (예: 코드 복잡도 제한, 명확한 자료형 지정 등)

### 실습 참고사항

* Rule 기반은 컴파일러 분석기로 검출 가능
* Directive는 사람이 설계/요구사항 검토 과정에서 판단

---

## MISRA-C 개요

* MISRA C는 자동차 산업 등 안전이 중요한 분야에서 사용하는 C 언어 코딩 표준
* 안전성, 이식성, 유지보수성 향상 목적
* Rule과 Directive로 구성되며, Rule은 다시 Mandatory, Required, Advisory로 분류됨

## 적절한 키워드 (static, const, volatile) 사용법

### const 키워드 사용 예시

```c
const int *ptr = &value;        // 포인터가 가리키는 값은 변경 불가
int * const ptr = &value;       // 포인터 자체는 변경 불가
const int * const ptr = &value; // 포인터도, 값도 변경 불가
```

### volatile 키워드 사용 예시

```c
volatile int sensor_value;
```

* 하드웨어 상태나 인터럽트 등 외부에서 값이 바뀌는 경우 사용

### static 키워드 사용 예시

```c
static int counter = 0;
```

* 함수 내부에서 선언된 경우, 함수가 끝나도 값 유지
* 파일 레벨에서는 외부에서 접근하지 못하도록 제한

### 관련 MISRA 규칙

* **Rule 8.13**: 외부에서 접근 가능한 전역 변수는 const로 선언할 것
* **Rule 8.10**: 전역 변수에는 반드시 static 또는 extern을 명시해야 함

## 다중 파일을 위한 헤더 파일과 소스 파일 구성

### 파일 구성 예시

```c
// file1.h
extern int g_counter;

// file1.c
int g_counter = 0;
```

### 헤더가드 사용 권장

```c
#ifndef FILE1_H
#define FILE1_H
// 선언부
#endif
```

### 관련 MISRA 규칙

* **Rule 8.1**: 헤더 파일에는 선언만 포함, 정의는 금지
* **Rule 8.2**: 외부 선언은 정의와 정확히 일치해야 함
* **Rule 8.3**: 함수의 선언과 정의는 반드시 일치해야 함
* **Rule 8.4**: 외부에서 사용되는 함수는 헤더 파일에 선언되어야 함
* **Rule 8.11**: 전역 객체는 static으로 제한하고, 필요 시 extern 사용
* **Rule 8.12**: 전역 객체는 반드시 초기화되어야 함

## 인라인 함수 활용 및 매크로 비교

### 매크로의 단점

* 디버깅 불편
* 타입 체크 불가
* 다중 평가로 인한 부작용 가능성

### 인라인 함수의 장점

* 타입 안정성 확보
* 디버깅 용이
* 부작용 방지

### 예시

```c
#define SQUARE(x) ((x)*(x))
inline int square(int x) { return x*x; }
```

### 관련 MISRA 규칙

* **Rule 20.7**: 매크로 정의 시 괄호를 적절히 사용할 것
* **Rule 8.5**: 정의된 함수는 반드시 선언되어야 함
* **Rule 8.10**: 모든 전역 객체에는 정의 여부를 명확히 하기 위해 `static`, `extern`을 반드시 명시할 것

## 함수 및 변수 이름 정의

### 함수 명명 규칙

* 동사 + 명사 구조
* 예시: `read_sensor_data()`, `calculate_average()`

### 변수 명명 규칙

* 소문자와 언더스코어 사용
* 전역 변수: `g_` 접두사, 정적 변수: `s_` 접두사
* 예시: `g_speed_count`, `s_index_buffer`

### 상수 명명 규칙

* 대문자 + 언더스코어
* 예시: `MAX_SPEED`, `BUFFER_SIZE`

### 관련 MISRA 규칙

* **Rule 5.4**: 서로 다른 스코프에서 동일한 이름 사용 금지

  * 예: 전역 변수 `data` 존재 시 지역에서도 같은 이름 사용 금지
* **Rule 5.1\~5.6**: 식별자의 사용 가능 문자, 길이, 중복 여부 등에 대한 제약

## 적절한 데이터 타입 정의

### Rule 7.2

* 명확한 크기와 부호를 가진 타입 사용
* 예시:

```c
uint32_t counter = 0;
int16_t temperature = -10;
```

### Rule 7.3

* 부호 있는 정수와 부호 없는 정수를 혼용하지 말 것
* 예시:

```c
uint16_t a = 100;
int16_t b = -10;
// int result = a + b;  // 위험한 혼용 사례
```

### Literal Suffix (접미사)

* 리터럴 뒤에 붙는 타입 식별자

  * `123U` → unsigned int
  * `0x1UL` → unsigned long
  * `3.14F` → float

## 기타 보충 규칙

### Rule 8.1

* 모든 정의는 정확히 한 번만 존재해야 하며, 다중 정의 금지

### Rule 8.2

* 선언과 정의는 반드시 일치해야 하며, 일치하지 않으면 링크 오류 가능성

### Rule 8.3

* 함수 선언과 정의는 동일해야 하며, 선언 누락 시 정적 분석이 어렵고 호출 오류 발생 가능

### Rule 8.4

* 함수 정의는 반드시 선언을 선행해야 하며, 선언은 헤더파일에 위치해야 함

### Rule 8.11

* 전역 객체는 `static`으로 제한하고, 외부 사용 시 `extern` 사용 권장

### Rule 8.12

* 모든 전역 객체는 선언 시 초기화되어야 함. 초기화되지 않으면 예상치 못한 값으로 동작할 수 있음
