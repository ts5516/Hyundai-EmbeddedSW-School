# 임베디드 시스템 하드웨어

## 1. 디지털 논리와 회로

### 디지털 시스템 개요

* 0과 1의 이진 값을 사용하는 시스템
* 아날로그 입력을 디지털 신호로 변환하여 처리

### 핵심 부품

* **트랜지스터**: 전류를 제어하는 반도체 소자
* **IC(집적 회로)**: 여러 트랜지스터를 집적한 회로 칩
* **무어의 법칙**: 18개월마다 트랜지스터 수 2배 증가

### 논리 회로

* **조합 논리**: 현재 입력만으로 출력 결정 (예: 반가산기)
* **순차 논리**: 입력 + 현재 상태에 따라 출력 결정 (플립플롭 기반)
* **래치/플립플롭**: 1비트 정보를 저장
* **레지스터**: 다수 플립플롭으로 구성, 일시적 데이터 저장
* **버스 구조**: 레지스터, 메모리, ALU 간의 데이터 공유 경로

### 조합 회로 응용

* **멀티플렉서(MUX)**: 다중 입력 → 1개 선택 출력
* **가산기(Adder)**: 반가산기, 전가산기, n비트 가산기 구성

> **중요 개념 체크**:
>
> * 조합 논리 vs 순차 논리의 차이
> * 플립플롭의 역할과 클럭 동기화

## 2. 컴퓨터 구조와 명령어 처리 흐름

### CPU 기본 구성 요소

* **Arithmetic Logic Unit (ALU)**: 산술 및 논리 연산 수행 (덧셈, 뺄셈, AND, OR 등)
* **Control Unit (CU)**: 명령어를 해석하여 제어 신호 생성
* **Registers**: 데이터와 주소를 임시 저장하는 고속 메모리

> ALU는 단순한 구성처럼 보이지만, ISA에서 정의된 명령어 수행의 핵심 연산을 담당하는 회로입니다. 명령어 처리 단계 중 Execute 단계에서 활성화되며, 연산 결과는 보통 레지스터에 저장됩니다. 면접에서는 ALU 자체보다 '어떤 명령어가 ALU를 트리거하냐'가 더 자주 질문됩니다.

### 컴퓨터 기본 구성 요소

* **CPU**: ALU + 제어 유닛(CU) + 레지스터
* **메모리**: 주기억 장치 (RAM)
* **I/O 장치**: 입력/출력 장치 (키보드, 모니터 등)
* **버스**: 데이터, 주소, 제어 버스

### 명령어 처리 과정 (Fetch → Decode → Execute)

CPU는 명령어를 처리할 때 세 단계를 거칩니다:

1. **Fetch (인출)**

   * \*\*프로그램 카운터(PC)\*\*가 현재 실행할 명령어의 주소를 가리킴
   * 이 주소에서 \*\*명령어를 메모리로부터 읽어와 IR(명령어 레지스터)\*\*에 저장함
   * PC는 다음 명령어를 위해 자동 증가함

2. **Decode (해독)**

   * IR의 내용을 **Control Unit**이 해석함
   * **Opcode**에 따라 연산 종류 결정 (산술, 제어, 메모리 접근 등)
   * 필요시 **주소 지정 방식**(직접/간접)에 따라 실제 주소를 결정함

3. **Execute (실행)**

   * ALU 또는 메모리 제어 논리에 따라 명령어 수행

     * 예: ADD 명령 → ALU가 두 레지스터 값을 더함
     * 예: STA 명령 → 레지스터 값을 특정 메모리 주소에 저장
   * 연산 결과는 레지스터 또는 메모리에 반영됨

> 이 세 단계는 모든 명령어 수행의 기본 흐름입니다. 면접에서 자주 '이 과정을 예제로 설명하라'는 질문이 나오며, 명령어 종류에 따라 각 단계에서의 동작이 달라지는 점을 아는 것이 중요합니다.

1. **Fetch**: 명령어를 메모리에서 읽어옴 (PC → IR)
2. **Decode**: Opcode 해석, 제어 신호 생성
3. **Execute**: 해당 연산 수행 (ALU or 메모리 접근 등)

### 명령어 구성 및 주소 지정 방식

* **Opcode (연산 코드)**: 어떤 동작을 할지를 나타냄 (예: 0001 = ADD)
* **Operand (피연산자)**: 데이터 혹은 주소
* **주소 방식**:

  * **직접 주소**: 명령어에 쓰인 주소가 바로 유효 주소 (예: LDA 100 → AC ← M\[100])
  * **간접 주소**: 명령어에 쓰인 주소가 '유효 주소가 있는 주소' (예: LDA @100 → AC ← M\[M\[100]])

> 직접 vs 간접 주소 지정은 메모리 접근 동작을 완전히 바꿉니다. 면접에서는 '간접 주소 방식이 왜 필요한가?', '어떤 경우에 유리한가?' 등이 자주 출제됩니다. 간접 방식은 포인터와 같은 구조에서 매우 중요하며, 여러 계층의 참조가 필요한 구조에 쓰입니다.

* **Opcode**: 연산 코드 (4비트)
* **Operand**: 주소 or 즉시값 (12비트)
* **주소 방식**: 직접/간접 주소 지정 방식

> **중요 개념 체크**:
>
> * Fetch → Decode → Execute 흐름 정확히 이해
> * 직접 주소 vs 간접 주소 개념 숙지

## 3. ISA (Instruction Set Architecture)

### ISA란?

* CPU가 이해하고 실행할 수 있는 기계어 명령어 집합

### 주요 ISA 예시

* x86, ARM, MIPS, RISC-V, TriCore 등

### 명령어 분류

* **산술/논리 연산**: ADD, SUB, AND, OR
* **데이터 이동**: LDA, STA, MOV
* **제어 흐름**: JMP, BUN, JZ, CALL
* **입출력 제어**: IN, OUT

### 어셈블리어와 고급 언어 관계

* 고급 언어(C 등)는 컴파일러 → 어셈블리어로 변환 → 기계어 생성

> **중요 개념 체크**:
>
> * Opcode, Operand 구조 및 예시
> * 조건 분기 명령어(JEQ, JL 등) 역할 이해

## 4. 인터럽트, 예외, 트랩

### 개념 정리

* **Polling**: 장치를 반복 확인 (CPU 자원 낭비)
* **Interrupt**: 외부 장치가 CPU에 작업 요청 (비동기)
* **Exception**: CPU 내부 오류 (동기) → 0 나누기, 페이지 오류 등
* **Trap**: SW가 의도적으로 발생시키는 인터럽트 (e.g., 시스템 콜)

### 처리 흐름

1. 현재 상태 저장 (PC, 레지스터)
2. ISR (인터럽트 서비스 루틴) 실행
3. 복귀 (RET 명령)

> **중요 개념 체크**:
>
> * Interrupt vs Exception vs Trap 차이
> * 인터럽트 서비스 흐름 숙지

## 5. 메모리 구조 및 캐시

### 메모리 종류

* **휘발성**: SRAM (빠름, 캐시용), DRAM (느림, 메인 메모리)
* **비휘발성**: ROM, EEPROM, Flash

### Flash 메모리 비교

| 종류   | 특징                    |
| ---- | --------------------- |
| NOR  | 임의 접근, 느림, 적은 용량      |
| NAND | 순차 접근, 빠름, 대용량 저장에 적합 |

### 캐시 메모리 계층 구조

* 캐시: CPU와 메모리 사이 고속 저장 공간 (보통 SRAM)
* 메모리 계층: 레지스터 < 캐시 < DRAM < SSD/HDD

### 캐시 매핑 방식

* **직접 사상**: 한 블록 → 한 캐시 위치
* **완전 연관**: 어디든 저장 가능
* **집합 연관**: n-way 방식으로 구성된 절충형

> **중요 개념 체크**:
>
> * 캐시의 필요성과 지역성 원리
> * 직접/완전/집합 연관 방식 차이 및 장단점

## 6. 메모리 맵과 I/O 방식

### 두 가지 방식 비교

* **I/O Mapped**:

  * 별도 명령어(IN/OUT), 별도 주소 공간 필요
  * 예: x86

* **Memory-Mapped I/O**:

  * 장치를 메모리처럼 접근 (Load/Store)
  * 예: ARM, TriCore 등

### 메모리 주소 맵

* 각 메모리/장치의 주소 범위를 명시한 표
* **CS(Chip Select)**: 주소값에 따라 특정 메모리/장치 선택

> **중요 개념 체크**:
>
> * Memory-Mapped 방식이 임베디드에서 기본
> * 주소 매핑과 CS 신호의 연관성 이해

## 7. 실습 예제 요약 (TriCore ISA 기반)

### 실습 1: 덧셈 연산

```c
int a = 10;
int b = -3;
int c = a + b;
```

→ MOV, ADD 명령 사용

### 실습 2: 조건 분기 (if)

```c
int x = 0;
int y = (x == 0) ? 1 : 2;
```

→ CMP, JEQ, MOV 사용

### 실습 3: 반복문 (for)

```c
int sum = 0;
for (int i = 0; i < 3; i++) sum += i;
```

→ MOV, ADD, CMP, JL, J 사용

> **중요 개념 체크**:
>
> * TriCore 명령어 동작 방식 숙지
> * 고급 언어 → 어셈블리 변환 로직 이해
