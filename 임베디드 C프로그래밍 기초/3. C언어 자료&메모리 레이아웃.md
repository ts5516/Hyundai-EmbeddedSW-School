# C언어 자료형과 TC375 메모리 구조 실습 정리

---

## 1. C언어 자료형 기초

### 기본 데이터 종류
- 정수형: `int`, `short`, `long`, `char`, `unsigned`
- 실수형: `float`, `double`
- 문자형: `char`
- 상수 표현: `0b` (2진수), `0x` (16진수), `0` (8진수)

---

## 2. 정수의 부호 표현과 보수 개념

### 부호 있는 정수
- 2의 보수 방식 사용
- 부호비트(MSB)가 1이면 음수
- -1 = 1의 보수 + 1

---

## 3. 부동소수점 (IEEE 754)

- 32bit: 부호(1) + 지수(8) + 가수(23)
- Bias = 127 (지수 저장 시 더함)
- 연산 오차 → `epsilon` 비교 필요

예:  
```c
if (fabs(a - b) < 1e-5) {...}
```

---

## 4. 오버플로우 감지

* 연산 중 carry 발생 여부를 통해 감지
* 부호 있는 연산의 overflow:

  * MSB 캐리와 MSB-1 캐리의 XOR 결과로 판단

---

## 5. 구조체와 공용체

### 구조체

* 서로 다른 타입의 변수 묶음
* 각 멤버는 별도 메모리 차지

### 공용체

* 한 메모리 공간을 공유
* 가장 큰 멤버 기준으로 메모리 결정

### 비트필드 구조체 + 공용체 응용

```c
struct bits {
  unsigned char a1 : 2;
  unsigned char a2 : 2;
  unsigned char a3 : 2;
  unsigned char a4 : 2;
};

union data {
  unsigned char ch;
  struct bits ch_bit;
};
```

→ `ch = 0b11100100`일 때 비트 단위로 해석 가능

## 5. 메모리 레이아웃 개요

| 영역      | 설명                     |
| ------- | ---------------------- |
| `.text` | 명령어 코드, Read Only      |
| `.data` | 초기화된 전역 변수             |
| `.bss`  | 초기화되지 않은 전역 변수         |
| `heap`  | 동적 메모리 영역              |
| `stack` | 함수 호출 시 지역 변수, 복귀주소 저장 |

---

## 6. Stack vs Heap

| 구분    | Stack    | Heap         |
| ----- | -------- | ------------ |
| 할당 시점 | 컴파일 타임   | 런타임          |
| 사용 방식 | LIFO     | 개발자가 직접 관리   |
| 해제 방식 | 자동       | 수동 (free 필요) |
| 사용 위험 | Overflow | Memory Leak  |

**자동차 SW에서는 heap 사용 금지**

* 예측 불가한 동작 방지 (MISRA C 규칙)

---

## 7. 구조체 메모리 정렬 및 `#pragma pack`

### 기본 정렬 규칙

* 구조체 멤버는 자신의 타입 크기만큼 정렬됨
* 예: `char` + `int` → padding 발생 (4바이트 정렬)

### `#pragma pack(n)`

* `pack(1)`: 패딩 없이 연속 정렬
* `pack(4)`: 기본 정렬 단위가 4바이트
* TC375 기본 정렬 단위는 4바이트

```c
#pragma pack(1)
struct A {
  char c1;  // 0
  int i1;   // 1 → 5 (패딩 없음)
};
```

---

## 8. 스택 동작과 레지스터

* 함수 호출 시 stack frame 형성

* 주요 레지스터

  * `ebp`: 프레임 기준 주소
  * `esp`: 현재 스택 포인터
  * `pc`/`eip`: 실행 명령 주소

* `call`: 복귀주소 push → 점프

* `ret`: 복귀주소 pop

* `push`: sp -= 4

* `pop`: sp += 4

---

## 9. CSA (Context Saving Area)

* 인터럽트, 함수 호출 시 context 저장
* TC375는 CSA 영역에 하드웨어 자동 저장
* Lower Context: A2~~A7, D0~~D7
* Upper Context: A10~~A15, D8~~D15

---

## 10. TC375 메모리 구조

* 3개의 CPU + 2 PFlash + 2 DFlash + 3 LMU
* 각 코어는 고속 접근용 메모리 보유

| 구성   | 설명             |
| ---- | -------------- |
| PSPR | 명령어 저장용 고속 RAM |
| DSPR | 데이터 저장용 고속 RAM |
| LMU  | 공유 전역 변수 저장용   |

---

## 11. Calibration 개념

### ECU Calibration이란?

* 실행 중인 ECU의 메모리 변수 값을 읽고 수정
* XCP (ASAM 표준 프로토콜) 사용
* Transport Layer: CAN, CAN-FD, Ethernet, FlexRay 등

### 장점

* **Rebuild/Flash 없이 실시간 수정**
* 변수 주소를 `.map` 파일로 확인해야 함
* 수정 시 `.hex` 파일 직접 편집 가능

---

## 12. Intel HEX 파일 구조

### HEX 레코드 구성

| 필드          | 설명                          |
| ----------- | --------------------------- |
| Start Code  | `:`                         |
| Byte Count  | 데이터 길이                      |
| Address     | 시작 주소 하위 16비트               |
| Record Type | 00: 데이터, 01: EOF, 04: 상위 주소 |
| Data        | 실제 데이터                      |
| Checksum    | 2의 보수                       |

### 주소 레코드 예시

```text
:020000040800F2 → 상위 주소 0x8000
```

### 데이터 레코드 예시

```text
:20 0000 00 [데이터 32바이트] CHKSUM
```

## 13. `.map` 파일과 `.hex` 파일 연결

### `.map` 파일 예시

```
.data.main.nation_C  0x80007EE4
```

→ 이 위치를 기준으로 `.hex` 파일에서 0x11 → 0x33 등 값 수정

---

## 14. Checksum 수정 방식

* 모든 바이트 합을 구함 → 1바이트로 자름 → 2의 보수

예:

```
합계: 0x8B → 보수: 0x75
```
